LANGCHAIN BASICS

What is LangChain?

LangChain is a framework that provides reusable building blocks for working with language models. Instead of calling an LLM API directly every time, LangChain lets you create reusable components that work together, such as prompt templates, chains, and output parsers.

Why it matters

When you call an LLM API directly, you may write the same prompts repeatedly and receive unstructured text. LangChain provides reusable templates, structured outputs, and ways to connect multiple steps.

The problem LangChain helps solve

02

CHAINS

Chains & LCEL

A chain is a connected sequence of steps. For example: prompt → LLM → parser. Instead of running each part separately, a chain connects them so the output of one step becomes the input for the next.

My understanding

I think of a chain like a kitchen preparation line: raw ingredients → chop → cook → serve. Each step passes its output to the next step.

LCEL: LangChain Expression Language

LCEL is LangChain's way of connecting components using the pipe operator |.

prompt | llm | parser
promptPromptTemplate with variables
llmLanguage model such as OpenAI or Gemini
parserConverts the output into a usable format

The pipe operator means that the output of the left side is passed as input to the right side.

03

PROMPTS

Prompt Templates

A prompt template is a reusable prompt with placeholders for variables. Instead of writing the same prompt manually each time, you write it once and fill in different values.

Simple example

"What is the capital of {country}?"

Usage

VariableResult
country = "Pakistan""What is the capital of Pakistan?"
country = "France""What is the capital of France?"
Why it matters

The prompt is written once and can be reused with different variables without repeating the same text.

04

STRUCTURED OUTPUT

Output Parsers

By default, an LLM returns free-flowing text. An output parser converts or interprets the LLM's response into a structured format so that a program can process the result more reliably.

Structured vs. unstructured

PLAIN TEXT

Harder for code to process

"The product costs $20 and has a rating of 5 stars."

Your code has to figure out where the price and rating are.

STRUCTURED JSON

Easier for code to process

{
  "price": 20,
  "rating": 5
}

Your code can directly access data["price"].

Common parsers

StrOutputParser for plain text, JsonOutputParser for JSON, and structured output using Pydantic models.

05

CONVERSATIONS

Memory & Conversation History

By default, each LLM call is separate. The model does not automatically remember previous messages. Memory means keeping track of conversation history and feeding it back into the model so it can refer to earlier context.

How memory works

01User message
02Conversation history
03LLM
04Response
05History updated
Why it matters

Conversational apps need context. Without memory, every question is answered in isolation.

WITHOUT MEMORY

User: "My name is Aiman"

LLM: "Nice to meet you, Aiman!"

User: "What's my name?"

LLM: "I don't know."

WITH MEMORY

User: "My name is Aiman"

LLM: "Nice to meet you, Aiman!"

User: "What's my name?"

LLM: "Your name is Aiman."

06

TOOLS

Tool Calling

Tool calling means giving an LLM the ability to request external functions instead of guessing answers. The model decides when a tool is useful and what arguments to pass to it.

Example: Calculator tool

01User asks: 125 × 48
02LLM chooses calculator
03calculate(125 * 48)
04Tool returns 6000
05LLM gives the answer

Key concepts

Tool schemaDescribes what the tool does and what arguments it accepts.
Tool executionThe actual function runs with the arguments provided by the LLM.
Result returningThe result goes back to the LLM, which forms the final response.
Why it matters

Some tasks need real data or computation. Tool calling lets the model request help instead of guessing.

07

LANGGRAPH

What is LangGraph?

LangGraph is a framework for building graph-based workflows. While a chain follows a fixed sequence, a graph lets the workflow take different paths depending on what happened earlier.

Chain vs. graph

CHAIN · FIXED
ABCD

Always follows the same sequence.

GRAPH · FLEXIBLE
A Decision B C

Paths can depend on decisions and state.

When to use graphs

Use graphs when a workflow needs decisions, repeated steps, or different paths based on conditions.

08

COMPARISON

Chain vs. Agent

CHAIN

Fixed and predictable

  • Predefined flow
  • Predictable sequence
  • Steps generally follow a defined order
  • No decision-making between steps
AGENT

Flexible and decision-based

  • Can decide what to do next
  • Can choose between actions or tools
  • Can follow different paths
  • Makes decisions based on context
ChainLike a conveyor belt: everything goes through the same stations in order.
AgentLike a manager: looks at the task and decides which worker should handle it next.
09

GRAPH BUILDING BLOCKS

LangGraph Core Concepts

A

Node

One step or unit of work in the graph. A node is a function that processes the current state and returns an update.

B

Edge

A connection showing where execution goes next. It determines which node runs after the current one.

C

Conditional Edge

A decision based connection. The next node depends on a condition like checking if a value is true or false.

D

State

The information carried through and updated during graph execution. State is passed from node to node and can be modified along the way.

Visual example

START
CHECK ORDER
CONDITION?
YES
PROCESS
NO
NOTIFY
END

START: Entry point.

Check Order: A node that checks the order status.

Condition: A decision that determines which path is taken.

Process / Notify: Different nodes based on the condition.

END: Exit point.

10

WHY GRAPHS?

Why Use Graphs?

Graphs are useful when a workflow needs:

Different pathsHandle different cases differently.
DecisionsLet the LLM or code decide what to do next.
State managementTrack and update shared information.
Repeated stepsLoop back when needed, such as retry logic.
Example

A customer support bot might check whether an issue is billing or technical. Billing issues can go to a billing agent while technical issues go to a technical support agent. This is graph-style logic because the next step depends on the situation.

11

ORCHESTRATION

Orchestrator Agents

An orchestrator agent, also called a router receives a task and decides which specialized agent or step should handle it. The orchestrator coordinates the work rather than doing every task itself.

The manager analogy

Think of an orchestrator like a manager

A manager does not clean the data or write every report themselves. They look at the task and assign it to the right team member.

Visual example

USER TASK
ORCHESTRATOR
ASpecialized agent
BSpecialized agent
CSpecialized agent
FINAL RESULT

Key concepts

RoutingThe orchestrator decides which agent to use.
SpecializationEach agent focuses on a specific task.
CoordinationThe orchestrator manages communication between agents.
Shared stateAgents can access and update shared information.
